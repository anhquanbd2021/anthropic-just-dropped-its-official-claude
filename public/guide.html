Type-by-type guide

One schema mistake, three exact boundaries

Each control in the lab checks a real Developer-track boundary: the tool schema shape, MCP boundary expectations, and prompt-cache invalidation. This page maps every control to the one failure only it catches.

Honest limits. The lab simulates the schema boundary in plain JavaScript — it does not call Anthropic APIs, but it does reproduce the deterministic failure mode the exam tests.

Start here

What this demo proves

The seeded build uses a generic functions[].parameters tool schema and a stale cache marker. Run the schema checkpoint on that build and the scenario fails every time. Switch to the Claude-specific build and the same scenario passes. The guide below explains why each boundary matters and what to assert in study sessions.

Feature 01

Seeded generic schema

Loads the exact wrapper many generic notes teach: functions[].parameters. Proves that a candidate who memorizes that shape cannot pass Claude's tool boundary.

Proves
Deterministic schema mismatch before model inference.
Key detail
The seeded build uses the same seed every time, so the failure is reproducible in study notes and exams.
Feature 02

Claude-specific schema toggle

Replaces the generic wrapper with tools[].input_schema. The lab asserts the exact keys Claude uses, including tools exposed through MCP.

Proves
Exact schema keys are required, not preferred.
Key detail
MCP tools still land inside Claude's tool boundary; MCP does not remove the need for input_schema.
Feature 03

Cache-break assertion

Checks whether a system or tool edit invalidated the cached prompt key. The generic assumption is "edit = broken cache"; the Claude-specific rule depends on which block changed.

Proves
Silent study failures where lucky cache state hides wrong assumptions.
Key detail
Pin one cache-break assertion before any live API call; randomness is not a substitute.
Feature 04

Evidence log

Shows the exact reason the scenario passed or failed. The log replaces vague statements like "study more" with inspectable state.

Proves
Study feedback is only useful when it names the exact boundary.
Key detail
Each verdict includes the schema kind, cache state, and prompt text.
Feature 05

Cache lamp

A single visual indicator for cache health: amber for stale, green for fresh. The lamp changes only when the lab's cache state changes.

Proves
Cache behavior is a first-class exam topic, not an implementation detail.
Key detail
The lamp stays stale on the seeded build until the schema and cache state are both updated.
Feature 06

API scenario

A small POSTable endpoint at /api/scenario mirrors the same schema-cache check the UI runs. Tests can drive the lab end to end without a browser.

Proves
The lab's core logic is testable outside the DOM.
Key detail
The endpoint returns the payload shape, not a live Claude response.
